# Select source rooms and append later

One issuer/asset remains one property. Initial import accepts a nonempty subset of immutable source unit IDs and complete terms only for selected rooms. Unselected rooms remain in source metadata; no local rental apartment, invented zero price/baseline or occupancy state is created. MULTI_UNIT remains the source asset mode even when one room is selected. Initial publication/owner activation follows existing source-ownership rules.

New property_source_units maps stable source unit ID to the local apartment; property_source_import_batches stores an immutable source snapshot/hash/time per successful batch. Composite foreign keys enforce matching property/apartment/batch scope; unique(property_id,external_unit_id) plus account/property locks prevent racing duplicates. The public/manual apartment create API continues to reject source properties. An internal service entry is used only after fresh source validation.

Append requires same account/issuer/subject, current persisted verification and consent, property version, unchanged approved ownership/legal metadata, a fresh source hash and unmapped selected source IDs. Provider I/O is outside the SQL transaction. Add selected rooms and batch/mappings atomically. Preserve old apartment IDs, terms, publication/occupancy, photos/location, receiving accounts, requests, agreement snapshots and financial records. Legal-source changes require reconciliation; this unit does not implement a new legal-evidence update command.

Contract source evidence for a newly authored agreement resolves the apartment's own source batch; old rooms retain their original batch. Existing saved documents are never rewritten. Legacy apartments without mappings still read the original property evidence. Timestamps for new source records are truncated to SQL datetime2(6) precision before persistence so reloading cannot change the source fingerprint.

V45 is additive and independently registered after V42; V43/V44 belong to a parallel billing-view PR. Legacy backfill uses only the saved snapshot and requires a complete unambiguous match for every existing apartment by normalized source code, area, bedrooms and bathrooms, with unique room/source IDs and equal counts. Unmatched properties are left unchanged and return SOURCE_UNIT_RECONCILIATION_REQUIRED. Re-running migration does not duplicate mappings or batches. No data/old snapshot is deleted or reset.

UI starts with no rooms selected, preserves typed terms while toggling, supports select-all/clear, labels existing hidden/published rooms and only renders selected forms. Source assets with remaining rooms stay selectable. The management portal links to the existing-property flow using propertyId; append reuses parent photos/location and never requests them again. Source/duplicate/version conflicts require explicit reload. Existing manual-right dossier flow is unchanged.
